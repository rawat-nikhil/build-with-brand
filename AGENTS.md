# Project structure

```
src/
├─ app/          routing only — page/layout/constants/page.scss
├─ components/
│  ├─ atoms/       smallest units; no internal component deps
│  ├─ molecules/   compose atoms
│  ├─ organisms/   compose molecules; full page sections and site chrome
│  ├─ templates/   page-level arrangement (site-shell)
│  └─ ui/          shadcn sink — regenerated by `shadcn add`, do not hand-edit
├─ content/     site data (services, contacts, socials, stats, navigation)
├─ types/       shared domain types
├─ providers/   React context providers
├─ lib/         framework-agnostic helpers (cn, isActiveRoute)
└─ styles/      globals.css + theme.css
```

## Layer rule

Imports may only point downward: `atoms <- molecules <- organisms <- templates <- app`.
An atom importing a molecule is an error, enforced by `no-restricted-imports` in
[eslint.config.mjs](eslint.config.mjs). `content`, `types` and `lib` must never import
from `components`. If two layers need the same type, it belongs in `src/types`.

## Component modules

Each component is a folder of three files, plus a barrel:

```
atoms/nav-link/
├─ nav-link.tsx
├─ nav-link.scss
└─ index.ts        export { NavLink } from "./nav-link";
```

Do not add layer-level barrels (`atoms/index.ts`) — they pull `"use client"` modules
into server graphs and defeat tree-shaking.

## Styles

Tailwind v4 (CSS-first, no `tailwind.config`). Tokens live in `src/styles/theme.css`
and are exposed as utilities through `@theme inline` in `src/styles/globals.css`.

Component SCSS uses BEM and reaches Tailwind through the `#globals.css` subpath import
declared in `package.json`, so the line is identical at every folder depth:

```scss
@reference "#globals.css";
```

Never use a relative path such as `@reference "../../app/globals.css"` — it breaks the
moment a component moves between layers.
